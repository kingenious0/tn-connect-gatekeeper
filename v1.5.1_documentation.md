### Core Architectural Features

#### 1. Official Smart Auto-Approval Queue
- **Real-Time Hooking:** Listens directly for the `'group.join-request'` event from WhatsApp.
- **Official Approvals:** Calls `client.sock.groupRequestParticipantsUpdate(groupJid, [participantJid], 'approve')`, ensuring 100% compliance with WhatsApp guidelines.
- **Startup Catch-Up:** A background scanner `scanPendingJoinRequests()` queries all whitelisted groups at boot, automatically queueing join requests that arrived while the bot was offline.
- **Human Pacing:** Approvals are spaced by a 60–120s delay for the first request, and 20–40s for subsequent queued approvals to mimic a human moderator.

#### 2. WhatsApp HD Multimodal Vision Eyes (Direct & Quoted Media)
- **Quoted Context Support:** A custom `detectMediaContext` helper detects direct media messages as well as quoted media messages (when a user replies to an image or video with `@TN Connect Super Bot.. what is this?`).
- **Vision Routing:**
  - **Images:** Routed through Meta's `meta-llama/llama-4-scout-17b-16e-instruct` on Groq (ultra-fast, advanced image analysis) with fallback to `gemini-2.5-flash`.
  - **Videos:** Routed natively through `gemini-2.5-flash` for multi-frame video understanding.
  - **Large File Fallback:** Video files larger than 8MB are safely down-scaled by extracting their pre-rendered `jpegThumbnail` buffer to prevent server memory exhaustion.
- **Prompt Enforcements:** Output is governed by `visionSystemPrompt`, enforcing concise, asterisk-free analysis.

#### 3. WhatsApp Visual Link Previews
- **Dual-Scraper Engine:** Detects the first link in a text message. Uses Microlink API to securely scrape rich metadata cards (title, description, image) from complex social sites (TikTok, Instagram, YouTube, Spotify). Falls back to a custom-agent HTML parser for static sites.
- **Caching Mechanism:** Caches scraped metadata card buffers in an in-memory `linkPreviewCache`. This guarantees that if a link is broadcasted to 30+ groups, it is crawled exactly once, dramatically speeding up subsequent sends (0.3ms from cache) and avoiding IP ban blocks.
- **Visual Card Injection:** Injects scraped metadata inside WhatsApp's native `externalAdReply` payload inside the message `contextInfo`.

#### 4. Supreme Active Conversational "Social Mode"
- **Wizard Trigger:** Whitelisted strictly for supreme owner `233597626090` (Kingenious). Direct commands `join convo` and `leave convo` launch interactive setup wizards in DM.
- **Persistent Whitelist:** Whitelisted groups are written to `active_convos.json` so active banter groups are preserved across Render container redeployments.
- **Organic Spontaneous Banter:** A 15% probability check evaluates incoming non-bot messages in whitelisted groups. When the check succeeds, the bot chimes in organically.
- **Context Tracking:** The bot reads the last 6 messages from `client.messageCache` (chronological order) and forwards them to a dedicated Llama 70B `socialSystemPrompt` to maintain context-appropriate, Gen Z-vibe banter (no cap, vibes, facts, no asterisks).
- **Presence Simulation:** Simulates natural typing by executing `client.sendPresence(jid, 'typing')` and waiting a random 3–6s delay before sending the message.

#### 5. Distributed Single-Instance Lock (conflict-disconnect prevention)
- **Heartbeat Coordination:** The active bot instance updates an `active_lock` heartbeat timestamp in Supabase every 20 seconds.
- **Startup Queue:** On boot, the new container reads the Supabase lock. If the active heartbeat is less than 45 seconds old, the booting container yields and polls the lock state every 5 seconds without connecting to WhatsApp.
- **Graceful Shutdown Interceptors:** Binds hooks to `SIGTERM` and `SIGINT` signals. Upon shutdown, the old container gracefully disconnects from the WhatsApp WebSocket (notifying WhatsApp that it is cleanly offline), deletes the lock row in Supabase, and exits. The polling container immediately logs in without session corruption.

#### 6. Smart Content Moderation & Bot Safety
- **Profanity Filter:** Checks incoming text against 100+ English and 60+ Twi insulting terms. Uses custom boundary regular expressions to avoid false positives (e.g. "class" is not flagged as "ass").
- **Link Deletion:** All links are instantly deleted in groups for non-admins (admins are exempt).
- **Fast Action:** Moderation operates on a swift humanized delay of 1–3s (`1000 + Math.floor(Math.random() * 2000)`) with 3 deletion retries spaced 2 seconds apart.
- **Tagging mentions:** Alert tags are sent using both the LID JID and Phone JID in the native `mentions` array to render them as blue clickable highlights that send push notifications.
- **Bot-Admin Isolation:** Using the `isJidMe` dual-identity JID/LID check, the bot tracks its own admin privileges. If not a group admin, the bot remains silent. If a group admin, it ignores non-admin commands/chit-chat while maintaining full moderation.

### Command Guide

#### Supreme Owner Commands (DM only, Kingenious `233597626090`)
* **`join convo`** / **`join conversation`** — Starts the interactive wizard to whitelist a group chat for active conversational banter.
* **`leave convo`** / **`leave conversation`** — Starts the interactive wizard to remove a group chat from active banter.

#### Admin Commands (DMs & Group Mentions, Admins only)
* **`broadcast`** / **`send`** / **`announce`** — Starts the dynamic Broadcast Wizard.
* **`broadcast to group X, Y: [message]`** — Conversations-based instant broadcast to specific groups by name or partial name.
* **`broadcast to group X, Y`** — Pre-selects groups and prompts for message body or media upload.
* **`lock all groups except [group names]`** — Locks all monitored groups to admin-only messaging except the listed exceptions.
* **`unlock all groups except [group names]`** — Unlocks all monitored groups for everyone except the listed exceptions.
* **`leave groups [names]`** / **`exit group [name]`** — Gracesfully exits the specified groups, cleans caches, and removes them from the Supabase registry.
* **`register`** / **`admin`** — Starts the admin registration process.

### Anti-Ban Protection Layers (v1.5.1)

1. **Intake Cooldown:** A strict 5-minute connection buffer during which the bot listens to events but does not execute any API outputs or messages.
2. **Min Interval:** All outgoing messages must respect an 8-second pacing interval between sends.
3. **Presence Indicators:** Sends a "typing" state before every message to emulate a physical user.
4. **Broadcast Pacing:** Spaces multi-group broadcasts with a safe, humanized delay (3–6s) per group.
5. **Deduplication & Cache:** Link Preview Cache prevents redundant crawling blocks; in-memory admin maps prevent database latency delays.
